# 余録 · YUROKU

个人的书影游记录：电影、日剧、漫画、动画、小说（轻小说 / 网络小说 / 一般小说）和游戏。每部作品记一个 0.0–10.0 的分数、一句话短评和一篇 Markdown 观后感。纯静态网站，没有构建步骤，托管在 GitHub Pages。

- 在线访问：https://yule1048596-art.github.io/yule-media-log/

## 页面

- **档案**（`#/`）：海报墙 / 列表 / 日记三种视图；按分类、状态、看完年份、殿堂、标签和关键词筛选，可按看完时间、评分、更新时间、发行年份或标题排序。
- **作品详情**（`#/w/<id>`）：每部作品都有自己的链接，可以直接分享；`←` `→` 翻看上一部 / 下一部。
- **统计**（`#/stats`）：收录数、平均分、殿堂、评分分布、分类、每年 / 每月看完、评分最高和常用标签，可按年份切换；每张图都能展开数据表。

## 录入

- 点右上角「记录」或按 `N`。输入作品名，可从 Bangumi（或维基百科）自动填写封面、原名、作者、年份和集数。
- 长评支持 Markdown：`## 小标题`、`**粗体**`、列表、`> 引用`、`||行内剧透||`，以及折叠剧透块：

  ```
  :::spoiler 标题
  被折叠起来的剧透内容
  :::
  ```

- 没有封面链接时，会按分类自动生成一张封面。

## 数据与同步

所有数据都在 `data/works.json`，格式与旧版兼容。网页上的修改会先存在当前浏览器里（右上角云朵图标出现小圆点 = 有未同步的修改），再用下面任一方式保存：

1. **推送到 GitHub**：在「数据与同步」里填一个 fine-grained token（只选这个仓库，权限 `Contents: Read and write`），点「推送修改」，网站约一分钟后更新。令牌只保存在当前浏览器，不会写进仓库。推送时会核对线上版本：如果数据文件已经在别处（比如另一台设备）被改过，会拒绝覆盖并提示你先备份、再拉取。
2. **本地文件**：「保存为 works.json」，覆盖仓库里的 `data/works.json` 后用 git 提交。

开始正式记录前，可以在「数据与同步 → 整理」里一键清除示例作品。

## 快捷键

`/` 搜索 · `N` 记录新作品 · `←` `→` 详情翻页 · `Esc` 关闭弹窗

## 本地预览

在项目目录运行：

```bash
python3 -m http.server 8791
```

然后打开 http://127.0.0.1:8791/ 。

## 部署到 GitHub Pages

仓库 `Settings → Pages → Build and deployment` 选择 `Deploy from a branch`，分支 `main`，目录 `/ (root)`。

改了 `styles/` 或 `js/` 里的文件后，把 `index.html` 里所有的 `v=` 版本号（两个样式表、import map 和入口脚本）一起改成新值再发布。GitHub Pages 会让浏览器缓存文件 10 分钟，不改版本号的话，刚打开过旧版的浏览器可能混用新旧文件。只改 `data/works.json` 不需要动版本号。
